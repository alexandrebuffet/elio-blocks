Made for the Block Editor

Feels native, because it is.

  1. A report, like the Query block

    The Weather block works like the Query block: it gets the forecast of a place and hands it to the blocks inside it. From there, everything is a block: temperature, wind, UV index, sunrise, the condition icon. Add them, remove them, reorder them, nest them in rows and columns.

  2. A Forecast Template, like the Post Template

    Hourly and daily forecasts repeat a Forecast Template you design once, the way the Post Template repeats inside a Query block.

  3. Start from a layout

    Pick Default, Minimal, Hourly or Daily Forecast, or start blank and build your own.

  4. Every design tool you expect

    Colors, typography, spacing and borders come from the standard block supports: the same panels as core blocks, your theme’s presets, theme.json included.

  5. Your site’s settings, respected

    Dates in your site’s language and formats, in the timezone of the location. Metric or imperial, site-wide or per block.

  6. What you see is what you get

    The editor shows the real forecast of your location, styled exactly as it will be on your site.

  7. Open-Meteo by default, open to more

    The weather comes from Open-Meteo, with no account and no key for non-commercial use, or with the key of a subscription. Weather providers are pluggable: Elio Blocks can add more, and so can your own code, through its PHP API.

On the front end

In the page from the first byte, fresh all day.

  1. Rendered on the server

    The weather is in the HTML your visitors and search engines get. No loading spinner, no layout shift.

  2. Kept fresh in the browser

    The Interactivity API, WordPress’s own front-end framework, updates the data without reloading the page. No jQuery, no heavy scripts.

  3. Cached, and private

    Forecasts are cached on your server, and your visitors’ browsers never contact the weather service: their IP address stays with you.

Is it free?

Yes, totally. It is released under the GPL, like WordPress.

Do I need an API key?

Not by default. Elio Blocks uses Open-Meteo, an open-source weather API that needs no account and no key for non-commercial use. For a commercial site, enter the API key of an Open-Meteo subscription in the plugin settings.

Can I use another weather provider?

Open-Meteo is the provider built in. Elio Blocks is made to welcome others: a provider is registered with a few PHP functions, the same way Open-Meteo is, so new ones can come with the plugin or from your own code.

Can I style the blocks?

Yes. Colors, spacing and typography come from the standard design tools of the Block Editor. Beyond that, use theme.json, block style variations or plain CSS.

Does it work with the Classic Editor, widgets or page builders?

No. Elio Blocks only provides blocks, for the Block Editor and the Site Editor.

What about my visitors’ privacy?

Every request to the weather service is sent by your server, never by your visitors’ browsers, and carries no data about them.

Where is the source code?

On GitHub (opens in a new tab), where the plugin is developed in the open. Issues and pull requests welcome.
